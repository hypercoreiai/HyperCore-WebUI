## What came of it
- Initial forced state: Possible `p200` values are 1, 3, or 4.
- Constraint 8: Because `pVoid < 4`, and cell 1 is Pulsar and cell 4 is Singularity, Void can only be in cell 2 or cell 3.
- CPU-side sampling is disabled. `nsys status --environment` reports: root privilege disabled, `kernel.perf_event_paranoid = 4`, `perf_event_open` Fail, "CPU IP/backtrace sampling will be disabled".
- Practical usage for this project: Note that the repo already carries Nsight-derived numbers in comments (`src/kernels/cuda/bf16_gemv.cu:94`, `src/kernels/cuda/gr.cu:190`, and `bench/results/2026-10-03-v100-prompt-attn/README.md`), but no `.nsys-rep` or `.ncu-rep` files are currently present in the tree, so those captures would need to be regenerated.
- `build_debug/hypercore` is 180,948,568 bytes, unstripped, with full DWARF on the host side and source-line info in every device cubin.
- `ncu` is not on PATH; it is at `/usr/local/cuda/bin/ncu`.
- No NVTX ranges. `grep -rn "nvtx" src/ include/` returns nothing, so an `.nsys-rep` will show CUDA API and kernel activity but no named engine phases.
- The toolkit headers are present (`/usr/local/cuda/include/nvtx3/nvToolsExt.h`), so adding ranges around prefill and decode would be a small follow-up, not a build change.
- State file `.mcp_test_state.json` updated to loop 124 with this result recorded; `jq` reads it back cleanly.
- GPU generation. `archs` is taken from the actual cards (`archs = sorted({int(x) for x in gpu.get("archs", [gpu["arch"]])})`, `setup.py:2891`) and passed as `-DCMAKE_CUDA_ARCHITECTURES={cuda_archs}` (`setup.py:2910`).
- CPU ISA. With no ISA floor, ggml-cpu is built with `GGML_NATIVE=ON` (`CMakeLists.txt:1228`), i.e.
- Rebuild triggers. The engine is recompiled when the source hash changes, or when a GPU is added whose arch is not in the existing fatbin (`new_arch = local and not set(archs) <= built`, `setup.py:2892`).
- A compile then keeps the generations it already had: `archs = sorted(built | set(archs))`.
- `nm engine/hypercore | grep -ciE "avx512|avx2|avx1"` returns 32 such symbols in the binary on this machine, so the generic engine still runs the AVX-512 path on an AVX-512 CPU.
- `./setup.sh` also runs a calibration (`tools/calibrate.py`) that measures the PC and writes `/home/ai-user0/.config/hypercore/settings.json`.

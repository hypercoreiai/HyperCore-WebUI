## What came of it
- What is in place Usage `--gen` maximises generation tok/s, `--prefill` maximises prompt tok/s, `--latency` minimises `prompt_ms + decode_ms`; all three are mapped to one maximisation score so a failed boot lands at the bottom of the range.
- `git check-ignore -v` confirms all four are ignored.
- `pytest optuna_tune/test_bayesian_tune.py -q` → 13 passed in 31.9s (covers DONE/INFO parsing, the argument builder including the on/off switches, seed determinism, the latency objective picking the minimum row, staged layer labelling, dry run launching nothing, and that both deliverables are written and the `.sh` passes `bash -n`).
- When the engine exited at boot (your trial 1: `vram=512, kv=fp16, pcie=0.33` at 131072 context is a plausible MTP/VRAM boot failure), Python flushed that buffer during GC and printed `Exception ignored while finalizing file <_io.TextIOWrapper name=5>`.
- `optuna_tune/engine_runner.py` now uses unbuffered binary pipes (`bufsize=0`) and closes them explicitly in the `finally`: Covered by `test_a_dead_engine_leaves_no_broken_pipe_at_finalisation`, which runs a stub that prints INFO then exits, and asserts stderr contains neither `BrokenPipeError` nor `Exception ignored`.
- That change also removed a latent deadlock: `select()` on a fd plus `TextIOWrapper.readline()` can miss data the wrapper has already buffered.
- The reader now does `os.read(fd, 65536)` into its own line buffer.
- Ctrl-C threw a traceback and wrote nothing `Sweeper.run()` now catches `KeyboardInterrupt` in both modes and returns a flag; `main()` still writes the CSV, `max_run_<model>.sh` and `max_run_<model>.json` from whatever was measured, and the JSON records `"interrupted": true` and `study.complete`.
- Each boot at 131072 context takes roughly a minute, so `--trials 40` is about an hour.
- State is in `.optuna_tune_state.json` (loop 3).
